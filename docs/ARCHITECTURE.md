# Архитектура

Микросервис умных калькуляторов ремонта и привязки каталога к видам работ. Язык: Python 3.12,
FastAPI. Принцип: **числа считает детерминированный движок, модели только понимают текст**.

```
 Источники каталога                         Офлайн-конвейер (воркер / загрузка по API)
 ┌────────────────────┐   нормализация    ┌──────────────────────────────────────────────┐
 │ Yandex YML фид     │──▶ Product ──────▶│ извлечение атрибутов (regex → LLM по цитате) │
 │ CSV / XLSX / JSON  │   (lxml, потоком) │ виды работ: правила (131) + TF-IDF-модель    │
 │ Bagisto стенд / HTML│                  │ тип калькулятора, помещения, свойства        │
 └────────────────────┘                   │ уверенность → авто / очередь проверки        │
                                          └───────────────┬──────────────────────────────┘
                                                          │ предрасчитанные метки
 Запрос покупателя                         ┌──────────────▼──────────────┐
 ┌───────────────┐     REST /api/v1        │ Индекс каталога (в памяти)  │
 │ сайт / виджет │────────────────────────▶│ отбор: жёсткие правила,     │
 └───────────────┘                         │ рейтинг, цена, остатки      │
                                           └──────────────┬──────────────┘
                              ┌───────────────────────────┴───────────────┐
                              ▼                                           ▼
                  ┌───────────────────────┐                  ┌────────────────────┐
                  │ Движок расчёта (Decimal)│                 │ Работы: ставки СПб │
                  │ геометрия, формулы,    │                  │ p25/медиана/p75,   │
                  │ упаковки, поправки      │                  │ объём по классу    │
                  └───────────┬───────────┘                  └─────────┬──────────┘
                              └──────────────┬─────────────────────────┘
                                             ▼
                        корзина (SKU, упаковки, цена) + explain + диапазон стоимости работ
```

## Слои

| слой | модули | роль |
|---|---|---|
| адаптеры каталога | `catalog/adapters/*`, `catalog/feed.py`, `catalog/stand_client.py` | любой формат → `Product`; YML-фид читается потоком (95 МБ, ~15 с), снимки с датой |
| виды работ | `knowledge/taxonomy.yaml`, `work_rules.yaml`, `ml/worktypes.py` | многометочная привязка с ролью (материал / инструмент / расходник) и уверенностью |
| прочие метки | `ml/rules.py`, `ml/classify.py`, `ml/match.py` | тип калькулятора, помещения, свойства, калибровка, очередь проверки |
| извлечение | `ml/extract.py` | атрибуты из характеристик и текста; LLM только по цитате, значения хранятся отдельно (`inferred`) |
| движок | `engine/*` | чистые функции без I/O: геометрия, материалы, упаковки (`Decimal`, округление один раз в конце), поправки |
| знания | `knowledge/*.yaml` | расходы по умолчанию, поправки, ставки работ, нормы; у каждого значения источник |
| сервис | `service/*` | комнаты, объект, корзина, стоимость работ, состав по классу ремонта |
| подбор | `recommend/*` | жёсткие правила помещений, рейтинг, остатки, сопутствующие, RAG-объяснение |
| API | `api/*` | FastAPI, OpenAPI 3.1, кэш (память / Redis), ограничение частоты, метрики Prometheus |
| оценка | `ml/worktype_eval.py`, `agreement.py`, `eval/`, `scripts/` | метрики, согласованность разметчиков, воспроизведение |

## Эндпоинты

| метод | путь | назначение |
|---|---|---|
| POST | `/api/v1/calc/property`, `/calc/room` | расчёт объекта / комнаты (условия работ в `conditions`) |
| POST/GET | `/api/v1/product/{id}/calc` | калькулятор на карточке товара |
| POST | `/api/v1/recommend` | подбор товаров |
| POST | `/api/v1/catalog/upload` | загрузка каталога (YML/CSV/XLSX/JSON, `.gz`) → фоновая разметка |
| GET | `/api/v1/catalog/upload/{job}` · `/review` | ход, время, результаты · очередь проверки |
| POST | `/api/v1/catalog/work-types/classify` | новый товар → виды работ за миллисекунды |
| POST | `/api/v1/catalog/work-review/{sku}` | ручная правка (всегда приоритетнее модели) |
| GET/POST | `/api/v1/catalog/*` (products, review-queue, review, rematch, match) | админка привязок |
| POST | `/api/v1/estimate/{id}/explain`, `/export` | объяснение через локальную LLM, XLSX / PDF |
| GET | `/health`, `/ready`, `/metrics` | эксплуатация |

## Модели и ресурсы

- Виды работ: правила + TF-IDF (символы и слова) + логистическая регрессия «один против всех»,
  58 МБ, обучение ≈ 47 с, разметка ≈ 0,2 с на 1 000 товаров на CPU ноутбука; GPU не нужен.
- Эмбеддинги (multilingual-e5, FRIDA, bge-m3) подключаются через `ml/embed.py`; на CPU
  e5-small даёт 27 товаров/с и +0,008 micro-F1, поэтому по умолчанию не используются.
- Локальная LLM (Ollama; Qwen3 / GigaChat 3.1 Lightning) нужна только для серых случаев, разбора
  текстового запроса и объяснений; без неё сервис работает на правилах и шаблонах. Внешних
  вызовов нет: адрес LLM вне локальной сети отклоняется.
- Развёртывание: `docker compose` (api, postgres, redis, ollama, мок стенда); без Docker —
  `uvicorn maxicalc.api.main:app` с `CATALOG_PATH=data/raw/products_final.json`.

## Надёжность и честность чисел

- Движок не вызывает LLM и не использует сеть; любая величина в ответе сопровождается `explain`.
- Модель без уверенности не принимается: ниже порога — очередь проверки; ручные правки переживают
  пересчёт каталога.
- Все справочные величины имеют источник (URL, цитата); где источника нет, это сказано в
  `docs/COEFFICIENTS.md` и `docs/CHECKPOINT_1.md`. Метрики в отчётах помечены REAL / SILVER / SYNTHETIC.
