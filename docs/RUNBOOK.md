# Runbook — день хакатона (7 ноября)

Цель: за **≤ 1 часа** после получения данных организаторов получить размеченный каталог,
рабочий API на их данных, сверку формул с их эталонами и честные метрики для питча.
Все команды запускаются из корня репозитория. `make` нет на Windows — используйте
эквиваленты `uv run …` из таблицы внизу.

## 0. Чек-лист до дня X (T−1 неделя)

- [ ] **Положение о хакатоне:** разрешён ли заранее написанный код? Если нет — по

      пересобрать код в день X.
- [ ] Ноутбук для демо: `uv sync`, затем `uv run pytest` (должно быть 200+ зелёных тестов).
- [ ] **Не проверено на этой машине (проверить на демо-ноутбуке):** `docker compose up`,
      Redis-кэш против настоящего Redis, шрифт для PDF (`PDF_FONT_PATH`), нагрузочный тест
      на целевом железе, k6.
- [ ] Офлайн-репетиция: выключить Wi-Fi и пройти раздел 2 (тест `tests/test_offline.py`

- [ ] Демо-данные: `uv run python scripts/make_demo_catalog.py --n 10000` (СИНТЕТИКА).

## 2. Загрузка: что смотреть в report.md

Команда завершится кодом **2** и понятным сообщением, если каталог непригоден.

1. **«Не найдены столбцы артикула / наименования»** — в сообщении перечислены найденные
   заголовки. Добавьте синонимы в `ALIASES` (`src/maxicalc/catalog/adapters/base.py`) и
   повторите (≈ 10 с). Заголовки с единицами («Цена, руб.») распознаются автоматически.
2. **«Распознанные / нераспознанные столбцы»** — убедитесь, что цена, категория и описание
   попали в распознанные. Нераспознанные сохраняются как характеристики.
3. **«Товаров с ценой: N из M»** — если ⚠, цены не распознаны, **сметы будут неверными**.
   Это тихая ошибка: проверьте именно эту строку.
4. **Разметка:** доля авто / на проверку. По умолчанию — только правила (высокая
   точность, ниже охват). Модель `--model` **не откалибрована на их каталоге**; используйте её
   только осознанно и говорите об этом.
5. **Готовность калькуляторов** — главный риск. Для каждого типа: какая доля карточек имеет
   данные для расчёта (расход, фасовка, размеры). Строки с ⚠ (< 50%): корзины по ним будут в
   основном предупреждениями. Найдите, в каком поле лежит расход/фасовка, и добавьте разбор:
   - структурное поле «Характеристика → значение»: `CHAR_KEYS` в `src/maxicalc/ml/extract.py`;
   - текст в названии/описании: регулярные выражения там же (`_SPREAD`, `_KG_M2`, `_M2_PACK`…);
   - после правки `uv run pytest tests/ml/test_extract.py` и повторить `dayof run`.

## 3. Эталоны организаторов → точность формул (главный балл за точность)

Переложите их эталонные значения в YAML (формат тот же, что `tests/golden/golden_cases.yaml`)
и запустите eval — расхождения видны сразу, каждое с ожидаемым и фактическим значением:

```yaml
# data/organizer_golden.yaml
cases:
  - id: org-001
    calc: paint_liters            # wallpaper_rolls | paint_liters | putty_bags | tile_packs |
                                  # grout_kg | laminate_packs | skirting_pieces | pack_cost |
                                  # adhesive_kg | waterproofing_kg | layer_kg
    kind: continuous              # pack = целое число упаковок (точное совпадение)
    inputs: {area: 30, spread: 10, layers: 2}
    expected: 6
    tolerance: 0.05
    source: "эталон организаторов, лист 1"
    verified: true
```
```
GOLDEN_EXTRA=data/organizer_golden.yaml uv run python eval/run_eval.py
```

**Параметры, которые пока являются НАШИМИ допущениями — сверяйте в первую очередь:**

| Параметр | Значение | Где менять |
|---|---|---|
| Запас плитки по раскладке | прямая 7%, диагональ 12%, «ёлочка» 15%, малая комната +3%, крупный формат +3% | `engine/materials/waste.py` |
| Расход плиточного клея (если нет в карточке) | таблица Ceresit CM 11 | `engine/materials/tile.py` (`ADHESIVE_FALLBACK`) |
| Затирка: толщина плитки 8 мм, шов 3 мм, плотность 1,6 | допущение (формула — Ceresit CE 79) | `service/room_calc.py` (`DEFAULT_GROUT_*`) |
| Обои: припуск 0,1 м, запас рулонов 0 | допущение | `service/room_calc.py` (`WALLPAPER_TRIM_M`) |
| Краска: 2 слоя; пористое основание +10% | допущение | `service/room_calc.py` (`PAINT_LAYERS`), `engine/materials/coatings.py` |
| Подложка, плинтус: запас 5%; ГКЛ: 10% | допущение | `flooring.py`, `skirting.py`, `drywall.py` |
| Шпатлёвка 2 мм, наливной пол 5 мм | допущение | `knowledge/presets.yaml` (`layers_mm`) |
| Доли комнат типовых объектов | эвристика | `knowledge/presets.yaml` |
| Электрика (розетки на м², кабель на точку) | эвристика | `knowledge/norms.yaml` |
| Правила помещений | наше прочтение плана | `knowledge/room_rules.yaml` |
| **Ставки работ** | **не заданы (null)** | `knowledge/work_rates.yaml` (заполнить, если дадут прайс) |

После правки: `uv run pytest` (тесты с ручными расчётами могут потребовать обновления — это
нормально, если эталон организаторов расходится с нашим допущением; зафиксируйте решение).

## 4. API на их данных

```
CATALOG_PATH=data/organizer/<файл> uv run uvicorn maxicalc.api.main:app --port 8000
uv run python scripts/smoke.py          # 9 проверок, причина по каждой ошибке
```
`smoke.py` с «каталог пуст» — не задан/не найден `CATALOG_PATH`. Swagger: `/docs`.
Демо-сценарий: `/v1/calc/property` (60 м², cosmetic/major) → корзина → экспорт XLSX/PDF;
карточка товара `/v1/products/{sku}/quantity`; `/v1/recommend` для «ванная + гипсокартон»
(показать, что небезопасный товар отсеян и **почему**).

## 5. Честные метрики для питча

```
uv run python scripts/dayof.py score data/dayof/spot_check.csv   # точность + интервал
uv run python scripts/measure_rematch.py data/organizer/<файл>   # время пересортировки
uv run python eval/run_eval.py                                   # (с GOLDEN_EXTRA)
uv run python scripts/pitch_metrics.py --spot data/dayof/spot_check.csv
```
Результат — `docs/PITCH_METRICS.md`. Генератор **сам** не даст заявить лишнего:
- точность авто-разметки «достигнута» только если **нижняя граница** 95% интервала ≥ 95%;
- все цифры на синтетике помечены «СИНТЕТИЧЕСКИЕ ДАННЫЕ»;
- экономию часов считает из измеренной нижней границы, а минуты на товар печатает как
  **допущение**;
- не измеренное печатается как «не измерено».

Что можно говорить со сцены: время пересортировки, задержки API (измерены на нашем
ноутбуке, один процесс), число эталонов и сколько сверено с документацией производителей,
измеренную на их данных точность с интервалом. Чего **нельзя**: точность ML «в целом» по
синтетике, стоимость работ (ставок нет), «95%» без прошедшей выборки.

## 6. Если что-то пошло не так

| Симптом | Действие |
|---|---|
| `dayof run` → код 2, «Не найдены столбцы…» | добавить синонимы в `ALIASES` (раздел 2.1) |
| Кириллица «кракозябрами» | CSV в Windows-1251 читается автоматически; для других кодировок пересохранить в UTF-8 |
| Все цены `null` | столбец цены назван нестандартно → `ALIASES["price"]` |
| Корзина = одни предупреждения | см. «Готовность калькуляторов»: в карточках нет расхода/фасовки |
| `smoke.py`: `recommend` не нашёл товаров | каталог не размечен: смотреть долю «на проверку»; нет категорий — правила дают меньше охвата |
| Экспорт PDF → 501 | нет шрифта: `PDF_FONT_PATH=<путь к DejaVuSans.ttf или arial.ttf>`; XLSX работает без него |
| `docker compose up` не стартует | запуск без Docker: `uvicorn` (раздел 4); Redis не обязателен для одного процесса |
| Несколько воркеров uvicorn | нужен `REDIS_URL`, иначе экспорт может попасть на воркер без сметы |
| API падает при старте с `FileNotFoundError` | неверный `CATALOG_PATH` (так и задумано: падаем сразу, а не молча с пустым каталогом) |
